# nd_storage spec validation report (11-JUL-2026)

Validation of nd-storage-interface-spec.md against the repository state before implementation. The three factual findings and sixteen gap decisions below are folded into nd-storage-design.md.

Spec: `Verilog/docs/nd-storage-interface-spec.md` (read in full).
Verdict up front: the spec is implementable, but **three claims are factually wrong** - (1) the device side is NOT "already built against" the section-4 contract (the floppy backend is a sector-level command port, not a block port; test 6's "map 1:1" is false), (2) the "leftover-cycles device port" does not exist and, worse, the current CPU mapping consumes the ENTIRE SDRAM address space, so there is no "high region" today, and (3) `sd_fat_check` cannot detect fragmentation, so it cannot enforce the contiguity rule as written.

## (a) Client contract vs ND-BUS-DEVICES - pin-for-pin

Device inventory: `Verilog/ND-BUS-DEVICES/` contains BUS-IF (ND_BUS_SLAVE.v), DMA (ND_DMA_MASTER.v), FLOPPY (ND_FLOPPY_PIO.v), TAPE-400 (ND_TAPE_400.v). Note `TAPE-400/sim/` is empty (its acceptance gate is the top-level `make test-tape`, per `Verilog/docs/device-bus-todo.md:98-102`).

### Buffer port (spec lines 85-99 vs `ND_FLOPPY_PIO.v:77-80`)

| Spec section 4 | ND_FLOPPY_PIO.v actual | Match |
|---|---|---|
| buf_addr[c] out [9:0] | `dbuf_addr` input [9:0] (line 77) | YES (width, direction) |
| buf_wdata[c] out [15:0] | `dbuf_wdata` input [15:0] (line 78) | YES |
| buf_we[c] out | `dbuf_we` input (line 79); sampled in the sysclk block, line 233-235 | YES, but sysclk-domain only |
| buf_rdata[c] in [15:0] | `dbuf_rdata` output reg [15:0] (line 80) | Width YES; **timing NO** |

Timing mismatch: spec line 96-97 says "address presented one cycle ahead, standard synchronous BRAM timing", but `dbuf_rdata` is **combinational** (`always @(*) dbuf_rdata = s_buffer[dbuf_addr];`, lines 180-183). nd_storage sampling one cycle late still works (data arrives early), so functionally compatible - but the device-side array will not infer BRAM with an async read port on Gowin; that is a device-side fix, not an nd_storage blocker. Also: `dbuf_we` is clocked by the floppy's `sysclk` block, so the buffer-master signals MUST be presented in the sysclk domain (see gap 1).

### Request/handshake port - this is NOT the spec contract

The floppy's disk backend (`ND_FLOPPY_PIO.v:63-74`) is a **sector-granular command port**, not the spec's block port:

| Spec section 4 | ND_FLOPPY_PIO actual | Mismatch |
|---|---|---|
| req pulse + wr bit | `disk_req` pulse + `disk_op[2:0]` enum (lines 65-66): FORMAT/WRITE/WRITEDEL/READID/READ/SEEK/RECAL/CTLRESET (only READ/WRITE/WRITEDEL/FORMAT reach the port, lines 306-320) | wr bit vs 3-bit op enum incl. FORMAT and WRITEDEL |
| block[15:0], 2048-byte block | `disk_sector[6:0]` (1-based) + `disk_track[6:0]` + `disk_format[1:0]` + `disk_drive[2:0]` (lines 67-70) | No block number exists; geometry -> LBA conversion is nobody's job yet |
| 1024-word block transfer | `disk_buf_start[9:0]` + `disk_wordcount[10:0]` = 64/128/256 words per SECTOR (lines 71-72, 132-133, 147) | One op moves 128-512 bytes at an arbitrary buffer offset, not a 1024-word block at offset 0 |
| busy level consumed by client | floppy has no busy input; it waits for `disk_done` (line 367) | Compatible (busy unused) |
| done + single err | `disk_done` + `disk_err_notrdy` + `disk_err_missing` (lines 72-74) | Two distinct error causes vs one err bit |
| open_req/open_ok/open_err/size_bytes | No such ports on the device | Nobody on the device side pulses open_req |

Consequence: spec line 97-99 ("This port is ALREADY implemented on the device side") and acceptance test 6 line 184-186 ("the disk_*/dbuf_* signals map 1:1") are **wrong**. A floppy backend adapter (analogous to section 5's tape adapter, but unmentioned in the spec) must: compute byte offset = (track*sectors_per_track + sector-1)*sector_bytes, derive block = offset>>11, do sub-block extraction on read and **read-modify-write of the containing 2048-byte block on write** (a sector never straddles a block boundary since 128/256/512 all divide 2048 - verified against the geometry at lines 130-133), implement FORMAT/WRITEDEL semantics, and map err causes. Sector ops within one block only, so single-block RMW suffices.

### Tape (spec section 5 vs `ND_TAPE_400.v:54-58`)

Matches: `byte_req` out pulse / `byte_valid` in pulse / `byte_data[7:0]` in / `source_rewind` out pulse - exactly the adapter port of spec lines 118-121 (name `source_rewind` vs "rewind", trivial). EOF behavior matches: RFT only rises on `byte_valid` (lines 124-135), so an unanswered byte_req leaves RFT low, exactly as spec line 121-124 describes. Clock: sysclk. No mismatch beyond the domain question (gap 1).

## (b) SDRAM reality vs spec assumption

What exists (all in `Verilog/fpga/tang-nano-20k/sdram-bridge/`):

1. **No second port exists.** `sdram18.v` has exactly one command port (`rd/wr/refresh/addr[20:0]/din[17:0]/dout[17:0]/data_ready/busy`, lines 48-58), and `MEM_RAM_49_SDRAM.v` instantiates it privately (lines 122-147) and owns refresh generation (lines 152-168, 297-303). The second device port is only a promise in `Verilog/docs/device-bus-todo.md:133-135` ("sdram18.v gets a second (device) port; CPU absolute priority"). nd_storage must request/define it; the natural place is a port-arbiter layer inside `MEM_RAM_49_SDRAM.v` (its `B_IDLE`/`B_POST` states already know when the CPU is guaranteed idle - the earliest next CPU access is N+11, line 297-300).

2. **There is no spare address region today.** The CPU bridge maps `{bank_q, row_q[9:0], AA[9:0]}` = all 21 bits (`MEM_RAM_49_SDRAM.v:264`), and `sdram18` decodes `addr[20:0]` over the whole 2M x 32 part (`sdram18.v:137-156`; capacity statement `MEM_RAM_49_SDRAM.v:17-19`, `Verilog/docs/nd120-dram-memory.md:234-241`). BANK0+BANK1 = 2M words = 100% of the physical address space; the only "spare" is the unused upper 14 bits of every 32-bit word. Spec section 2/6 ("high region = disk-image slots") therefore requires an explicit decision - see gap 9.

3. **No burst.** `BURST_LEN = 1` (`sdram18.v:90`), each rd/wr is a 5-cycle op with no overlap (header line 13). A "block burst" is really 512-1024 sequential single-word ops. At 54 MHz with CPU interleave that is roughly 50-100 us per 2048-byte block - fine against every device budget, but the spec's "SDRAM burst read ... microseconds" (lines 47-49, 143) should read "tens of microseconds".

4. **Width/lanes.** The controller moves an 18-bit word per 32-bit SDRAM word, writes all four DQM lanes (`sdram18.v:174`), no byte access. 16-bit block data maps either one-word-per-SDRAM-word (wasteful: 2 bytes used of 4) or two-16-bit-words-per-SDRAM-word using the DQM lanes the die already has (`sdram_model.v:66-69` proves lane masking works) - the device port must define this; the 18-bit port cannot express it.

5. **Clock domain.** Everything in the bridge runs on `clk2x` (2x OSC = 54 MHz on Tang, 180-degree `clk2x_sdram` for the chip; `MEM_RAM_49_SDRAM.v:62-64,114`). OSC-domain signals are treated as synchronous because both clocks come from one rPLL at an integer ratio (`MEM_RAM_49_SDRAM.v:171-177`, `nd120-dram-memory.md:207-211`). The device port nd_storage gets will be in the **clk2x** domain; the sysclk<->clk2x relationship is fixed-phase, not a true CDC.

What nd_storage can rely on TODAY: nothing - every SDRAM interface is private to the CPU bridge. What must be added: a device command port (word address + 16- or 32-bit data + rd/wr/busy/data_ready) arbitrated at absolute-CPU-priority inside `MEM_RAM_49_SDRAM.v`, plus the address-space partition decision.

## (c) SD-FAT reuse assessment

- **Preload via `sd_file_reader` outen/outbyte: YES.** The reader streams the entire found file as a gap-free byte stream with `outen` pulses (`sd_file_reader.v:76-79, 716-728`), exactly what `sd_fat_test_top.v` buffers today (f_outen -> file_buf, lines 836-845). Two caveats: (i) it always streams the WHOLE file from byte 0 - you cannot request a block, which matches the full-slot preload model exactly; (ii) **no backpressure** - `outen` fires at the SD bit rate (about 0.8 MB/s at the 27 MHz / CLK_DIV=2 setting, `sd_reader.v:14-17`), so nd_storage needs a small smoothing FIFO/sector buffer in front of the SDRAM port (gap 13). Re-open = the reset/park pattern (`sd_fat_test_top.v:126-131`). A 1.2 MB floppy image preloads in roughly 2-4 s; the 46 KB max BPUN in well under 100 ms.
- **Write-through via `sd_writer` + `found_file_first_sector` + 4*block: YES, proven.** Exactly the WRBLK1 framing: `tgt_sector <= file_first_sector + {25'b0, BLK_NO, 2'b00}; nsec <= 4` (`sd_fat_test_top.v:1330-1344`); `found_file_first_sector` export at `sd_file_reader.v:692`. `sd_writer` needs an already-initialized card and the pin mux (header `sd_writer.v:4-10`; mux at `sd_fat_test_top.v:445-452`), and sources bytes through a registered 1-clk read port (`sd_writer.v:56-58`) - nd_storage must unpack 16-bit words to bytes; the proven byte order is **big-endian** (even byte = word MSB: `blk_pat` at `sd_fat_test_top.v:875-878`). Pin this in the spec (gap 10).
- **One engine shared: YES, with an ownership FSM.** `sd_fat_test_top.v:295-306` already muxes the single `sd_writer` between the data loop, `sd_fat_rewrite` (fx_busy) and `sd_fat_check` (ck_busy), serialized by the top FSM. The real constraint is the **card pins**: reader and writer cannot run concurrently (`phase_write` mux, lines 448-452), and the reader has no pause - so an open/preload and a write-through are mutually exclusive, full stop. SDRAM-served reads have no card dependency and CAN proceed during a preload if the arbiter separates "card owner" from "SDRAM port owner" (gap 7).
- **`sd_fat_check` at mount: reusable BUT insufficient** - see gap 16. Also note it needs the caller-captured root-entry table (`sd_fat_test_top.v:324-341`), i.e. a LIST-mode scan pass, which nd_storage's fixed-name open does not naturally perform; checking just the opened file's chain is a light extension.
- **Clock domain: the whole SD-FAT stack is single-clock 27 MHz** (`sd_fat_test_top.v:48-50, 94-96`; reader/writer divide the SD bit clock with enable-style dividers). On the ND-120 Tang build OSC = sysclk = 27 MHz, so the storage core can live in **sysclk** and the only crossing is the fixed-phase sysclk<->clk2x SDRAM port.

## (d) Gaps and contradictions - numbered, with proposed decisions

1. **Spec section 4 CDC sentence is self-contradictory** ("All signals in the storage clock domain; the bus-device side runs in the CPU sysclk domain - the CDC is INSIDE nd_storage", lines 58-61). If the CDC is inside nd_storage, its client ports are by definition in sysclk - and they must be, because `dbuf_we` is sampled by the floppy's sysclk block (`ND_FLOPPY_PIO.v:198,233`). *Decision:* client ports in sysclk; nd_storage core in sysclk (= 27 MHz Tang OSC, same clock the SD-FAT stack already uses); only the SDRAM device port is in clk2x, handled as a fixed-phase 1:2 transfer like the existing bridge, not with 2-flop synchronizers. Delete the "storage clock domain" wording.
2. **buf_addr [9:0] vs 2048-byte blocks: consistent.** 1024 x 16-bit words = 2048 bytes = 4 x 512-byte sectors. Confirmed everywhere (floppy buffer 1024x16 `ND_FLOPPY_PIO.v:93-94`; WRBLK1 framing; cache rule `device-bus-todo.md:116-122`).
3. **size_bytes[31:0] vs block[15:0]: consistent.** 65536 x 2048 = 128 MB max file; v1 slots are <= 2 MB. No action; note the limit for Phase-4 SMD (37-75 MB still fits).
4. **Tape slot 64 KB vs BPUN size: acceptable.** Largest BPUN in the repo is about 46 KB (`device-bus-todo.md:137-138`), and the proven sd-fat-test buffer had the same 64 KB limit (`sd_fat_test_top.v:75`). SLOT_SIZE is already a per-client parameter; an oversize file cleanly yields open_err (spec line 133-134). Keep 64 KB default.
5. **open_req while a block op is in flight: unspecified.** *Decision:* latch open_req like a request; drop open_ok for that client immediately (its reads must stop); execute the open as an exclusive card-owner phase after the in-flight block op completes. A client's own open_req while its req is pending aborts the pending op with done+err.
6. **"may IGNORE a req while busy" vs glitchy devices: non-issue as built, but tighten the wording.** Both device cores emit registered 1-cycle pulses in sysclk (`ND_FLOPPY_PIO.v:227-230,316`; `ND_TAPE_400.v:100-127`) - no glitches possible, and with client ports in sysclk (gap 1) there is no strobe CDC at all. *Decision:* keep "client must not pulse req while busy"; specify that nd_storage samples req only when busy=0 and open_ok=1, and that req while busy is silently lost (busy is the client's flow control).
7. **Open/preload vs the round-robin arbiter: must be a separate exclusive phase.** A preload monopolizes the card pins for seconds (see (c)); it cannot be a round-robin "block op", or spec section 3's worst-case analysis (N-1 block ops) is broken. *Decision:* two-level arbitration - a card-owner FSM (IDLE / OPEN(c) / WRITE-THROUGH(c)) above the round-robin block arbiter; during OPEN, SDRAM-served block reads for other open clients keep running; write requests stay pending until the card frees. Document that opens normally happen at mount time when devices are idle.
8. **Card re-init / reader park ownership: give it to nd_storage.** *Decision:* nd_storage owns the reader's rstn (the park/re-run pattern of `sd_fat_test_top.v:126-131`), the phase_write pin mux, and exposes only raw SD pad signals (`sd_clk`, `sd_cmd_i/o/oe`, `sd_dat0_i/o/oe`) - the board top contributes the two pad tristates and nothing else (repo no-z rule, `sd_fat_test_top.v:41-43,445-452`).
9. **The SDRAM partition does not exist (biggest gap).** See (b)2: CPU mapping covers all 2M words. *Decision to propose to Ronny (needs his sign-off - it changes detected CPU memory size):* depopulate BANK1 in `MEM_RAM_49_SDRAM.v` the same way BANK2 already is (boot sizing then detects one 1M-word bank = 2 MB CPU RAM), freeing addr[20]=1: 1M x 32-bit = 4 MB. Give the device port 32-bit data (two 16-bit words per SDRAM word via the existing DQM lanes) so the 4 MB is fully usable; slot defaults then become tape 64 KB + floppy 1.5 MB x2 + ~1 MB spare (an ND floppy image is ~1.2 MB per `device-bus-todo.md:123`). The spec's "floppy 2 MB each" default (line 129) does not fit any packing option and must shrink.
10. **Word/byte endianness on the card is unpinned.** *Decision:* big-endian (even byte offset = word bits 15:8), matching the hardware-proven WRBLK1 pattern (`sd_fat_test_top.v:875-878`) and BPUN byte order. State it in section 4's data-path paragraph; the tape adapter unpacks SDRAM words in the same order.
11. **The floppy needs a backend adapter the spec never mentions** (see (a)): geometry->block conversion, sector RMW on write, FORMAT/WRITEDEL semantics, err mapping (out-of-range -> disk_err_missing; open_ok=0 -> disk_err_notrdy). *Decision:* add `nd_storage_floppy_adapter` to section 5 as a sibling of the tape adapter, and rewrite acceptance test 6 to go through it.
12. **Nobody pulses open_req.** Devices have no open ports; tape `source_rewind` is pointer-reset only (spec line 122: no card access). *Decision:* board top auto-pulses open_req for each configured client after reset (with retry on open_err), and re-pulses on a console/button action for card swap. Keep it out of the device cores.
13. **Preload data path contradicts "nd_storage never stores payload"** (line 92-93). The reader's unpausable ~0.8 MB/s byte stream needs smoothing into 5-cycle SDRAM word ops that lose arbitration to the CPU. *Decision:* allow one sector-to-block-sized internal FIFO for the preload/write-through paths; restate the rule as "nd_storage never stores CLIENT-VISIBLE payload - client data lives in the client's buffer or SDRAM".
14. **buf_rdata timing wording vs the combinational device port** - compatible as analyzed in (a); *decision:* keep the spec's "sample one cycle after address" rule (it works against both async and registered client buffers) and note the device side should migrate to a registered read for BRAM inference.
15. **err is one bit; the floppy distinguishes not-ready vs missing.** *Decision:* keep err as one bit on the client port; cause resolution lives in the floppy adapter (gap 11). Optionally add a 2-bit err_code valid with done - cheap now, breaking later.
16. **`sd_fat_check` does NOT detect fragmentation.** Its verdict is `bad || chain_len != expct` (`sd_fat_check.v:373`) - a fragmented chain of correct length passes OK, so spec line 139-141 ("sd_fat_check can verify ... fail open_err on a fragmented file") is currently false. *Decision:* add a per-file `contig` flag to sd_fat_check (one comparator: next_cluster == current+1 during C_WALK, around lines 285-297), OR have nd_storage verify contiguity itself during preload (it already knows first_sector and can cross-check `found_file_first_sector + 4*block` math only holds for contiguous files). The check-extension is the cleaner and reuses the mount-time CHECK run the spec already wants. Note reads are safe either way - the reader follows the FAT chain, so a fragmented file preloads correctly; only write-through corrupts.

## (e) Test infrastructure notes (spec section 9)

- **Registry**: `Verilog/tests/run_all_tests.sh` - format `<dir relative to Verilog/> :: <make target> :: <pass regex>` (lines 16-18), fail-fast, output must not contain FAIL and must contain the pass pattern (lines 103-115); convention `TB_RESULT: PASS`. SD-FAT entries already exist at lines 55-59; the six nd_storage tests slot in as new `SD-FAT/sim` targets (or a `SD-FAT/sim` + system entry) with strict patterns.
- **SD card model**: `Verilog/SD-FAT/sim/sd_card_model.v` covers CMD17/CMD24 with image file load and CRC checking - sufficient for tests 1, 2, 3, 4, 6. **It has no error-injection hook** (unknown commands just time out, lines 205-252): test 5's "write failure injected in the card model" requires adding a fault input/parameter (e.g. answer CRC status != 010, or suppress the response). Small, but it is new work.
- **SDRAM model**: `fpga/tang-nano-20k/sdram-test/sim/sdram_model.v` (2M x 32, CL=2, DQM byte masking, auto-precharge-tolerant) is suitable - it is exactly what the sdram-bridge tb already links (`sdram-bridge/sim/Makefile:9`); **sdram-bridge/sim has no separate/better model**. DQM support matters if gap 9's packed 32-bit device port is adopted. For pure nd_storage unit tests a port-level stub behind the new device port is faster than the full chip model; use the chip model for the bridge-arbiter test.
- **Simulator choice**: the pure-iverilog full-stack SD sim takes 30-60 min and is deliberately unregistered (`run_all_tests.sh:70-72`, `sd-fat-test/sim/Makefile` header) - the registered path is Verilator with a **C++ SD card model inside `sd-fat-test/sim/test_sd_fat.cpp`**. The nd_storage system test (test 6, full stack with the floppy) should follow that Verilator pattern to stay registry-viable; iverilog remains fine for tests 1/3/5 with the SDRAM stub.
- **fsck gate**: reusable as-is for test 2 - the tb writes the post-image and the Makefile runs `fsck.vfat -n` (`sd-fat-test/sim/Makefile`, test-verilator / test-verilator-fat32 targets, including the documented FSInfo-drift tolerance on FAT32).
- Floppy tb precedent: `ND-BUS-DEVICES/FLOPPY/sim/nd_floppy_pio_tb.v` already drives the disk_*/dbuf_* port with an image-backed model (registered line 62) - test 6 replaces that model with the real nd_storage + floppy adapter stack, which is the cleanest proof that the adapter (gap 11) closes the contract.
