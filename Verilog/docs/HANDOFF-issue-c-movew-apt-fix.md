## What Issue C was

MOVEW with source=APT and destination=APT drops the word written at the
destination page boundary. Root cause (MEASURED, then schematic-verified on
DELILAH.pdf page 25, CGA/MAC/DECODE sheet 1 of 4, and independently confirmed
wrong in the Logisim schematic by Ronny):

- File: Verilog/DELILAH-CPU/CGA_MAC/circuit/CGA_MAC_DECODE.v
- GATES_5 third input was `s_cscomm_4`; the schematic shows ICSMIS0
  (= `s_csmis_0_n`). Consequence: for CSCOMM 0o34/0o35 (RDRQ/WRRQ) with
  CSMIS=1 (APT), BOTH SPT and SAPT asserted -> the PTSEL JK flip-flop
  (J=SPT, K=SAPT, MCLK-clocked) TOGGLED instead of selecting APT -> from the
  APT state it flipped to PT -> wrong page table consulted at the destination
  first-touch -> spurious level-14 page fault killed the in-flight boundary
  write. APT->APT only.
- The fix is IN the file (with a 31-JUL-2026 comment block at GATES_5) but
  UNCOMMITTED. Ronny fixed the same error in the Logisim schematic himself.

Signal-naming trap in that file: `s_cscomm_N` = ~CSCOMM[N] (inverted),
`s_cscomm_N_n` = CSCOMM[N] (true); same for csmis. NAND/NOR via BubblesMask.
